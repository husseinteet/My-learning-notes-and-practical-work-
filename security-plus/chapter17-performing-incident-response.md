# Security+ Chapter 17 – Performing Incident Response

## Main Idea

This chapter explains the Incident Response (IR) process, including preparation, detection, analysis, containment, eradication, recovery, and lessons learned. Effective incident response helps organizations minimize damage, restore operations, and improve future security.

---

## Incident Response

Incident Response (IR) is a structured process used to detect, analyze, contain, and recover from cybersecurity incidents.

### Objectives

- Minimize business impact
- Contain security incidents
- Restore normal operations
- Preserve evidence
- Improve future defenses

---

## Incident Response Lifecycle

Most organizations follow a six-phase incident response process.

### 1. Preparation

Preparation ensures the organization is ready before incidents occur.

**Activities:**

- Develop incident response plans
- Create communication procedures
- Train personnel
- Deploy security tools
- Perform regular backups

---

### 2. Detection and Analysis

Security teams identify and verify potential incidents.

### Common Detection Sources

- Security Information and Event Management (SIEM)
- Intrusion Detection Systems (IDS)
- Antivirus alerts
- Firewall logs
- User reports

### Analysis Tasks

- Determine attack scope
- Identify affected systems
- Assess severity
- Collect evidence

---

### 3. Containment

Containment limits the spread of an attack.

### Short-Term Containment

- Disconnect infected devices
- Block malicious IP addresses
- Disable compromised accounts

### Long-Term Containment

- Apply temporary fixes
- Patch vulnerable systems
- Strengthen monitoring

---

### 4. Eradication

Remove the root cause of the incident.

### Common Actions

- Remove malware
- Delete malicious files
- Patch vulnerabilities
- Reset compromised credentials

---

### 5. Recovery

Restore systems to normal operation.

### Recovery Activities

- Restore backups
- Monitor systems
- Verify security controls
- Return services to production

---

### 6. Lessons Learned

Review the incident after recovery.

### Goals

- Identify weaknesses
- Improve response procedures
- Update documentation
- Train personnel

---

## Incident Response Team (IRT)

An Incident Response Team coordinates incident handling.

### Team Responsibilities

- Investigate incidents
- Collect evidence
- Communicate with stakeholders
- Coordinate recovery
- Document findings

---

## Incident Classification

Security incidents are classified based on severity.

### Factors

- Business impact
- Data exposure
- Number of affected systems
- Recovery complexity

---

## Evidence Collection

Evidence must be collected carefully to support investigations.

### Types of Evidence

- Log files
- Memory captures
- Disk images
- Network traffic
- System snapshots

### Best Practices

- Preserve original evidence
- Record timestamps
- Maintain documentation
- Protect integrity

---

## Chain of Custody

Chain of Custody documents who handled evidence from collection through investigation.

### Purpose

- Maintain evidence integrity
- Support legal proceedings
- Prevent tampering

---

## Communication During Incidents

Effective communication reduces confusion during incident response.

### Internal Communication

- Security team
- IT administrators
- Management
- Legal department

### External Communication

- Customers
- Business partners
- Regulatory agencies
- Law enforcement

---

## Incident Documentation

Every incident should be fully documented.

### Documentation Includes

- Timeline
- Systems affected
- Root cause
- Actions taken
- Recovery status
- Lessons learned

---

## Security Tools Used During Incident Response

### SIEM

Collects and analyzes security events from multiple systems.

### EDR

Provides endpoint monitoring and rapid threat response.

### IDS/IPS

Detects and prevents malicious network activity.

### Packet Capture Tools

Analyze network communications during investigations.

---

## Root Cause Analysis

Root Cause Analysis identifies why the incident occurred.

### Benefits

- Prevents recurrence
- Improves security controls
- Supports continuous improvement

---

## Incident Response Best Practices

- Maintain updated response plans
- Conduct regular incident response exercises
- Monitor systems continuously
- Keep security tools updated
- Document every incident
- Review lessons learned after recovery

---

## Key Takeaway

Effective incident response follows a structured lifecycle of preparation, detection, containment, eradication, recovery, and lessons learned. Proper planning, evidence preservation, communication, and continuous improvement help organizations reduce the impact of cybersecurity incidents and strengthen future defenses.
